# Google Maps on Google Sheets: setup guide and demo

A step-by-step guide for going from a brand-new Google account to a Google Sheet that calls the
Google Maps APIs, plus a tiny demo app that proves each piece works. Most of the effort in a project
like this is Google account, billing, API key and permission setup, so that is what the guide covers.

## What you end up with

A Google Sheet with a **Maps Demo** menu, backed by an Apps Script project that is linked to a
billing-enabled Google Cloud project holding your Maps API key:

- **Geocode selected cell**: turns an address in a cell into latitude and longitude, using the
  Geocoding API from Apps Script's servers.
- **Show selected cell on map**: shows that address on a map in a dialog, using the Maps
  JavaScript API in the browser.

## Quick start

1. Use Linux with Nix (the scripts assume NixOS). From the repo root, run `nix-shell`. It provides
   node, the gcloud CLI and clasp.
2. Open [`init_setup/SETUP.md`](init_setup/SETUP.md) and follow it from the top. It covers the
   account, billing, project, API key, consent screen, Sheet creation, pushing the demo, and
   checking the logs.

Use a private (incognito) browser window for every step that involves a Google account. The guide
explains why.

## Layout

| Path | What it is |
|---|---|
| [`init_setup/SETUP.md`](init_setup/SETUP.md) | The setup guide, with appendices on credentials, tokens, OAuth and how Sheets, scripts and projects fit together |
| [`init_setup/`](init_setup/) | The scripts the guide runs: create the project, create the Sheet, push the demo, view logs |
| [`demo/`](demo/) | The demo app: plain Apps Script files pushed with clasp, with no build step |
| [`demo/COMPONENTS.md`](demo/COMPONENTS.md) | What each part of the demo does and which Google API it calls |
| [`OAUTH.notes.txt`](OAUTH.notes.txt) | Raw notes on OAuth consent, test users and scopes |
| `maps_config.env` | Generated by the scripts and git-ignored. Holds your project ID, script ID and API key, so never commit it |

## Running the demo's tests

The address-parsing logic is a pure function with unit tests that need only Node:

```
node --test demo/test/geocode.test.js
```
